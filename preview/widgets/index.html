Checklist checklist

v1.0.0 interactive web component

A personal to-do list for setup steps or readiness checks. Progress is remembered in the learner's browser. Not graded.

Live example

Copy this into your page

```checklist
title: Before your first task
items:
  - text: Open a Git repository and create a branch
    hint: Codex works best when you can diff and revert.
  - Sign in with your ChatGPT account
  - Check permissions with `/status`
done: You are ready to start.
```

Weak vs strong prompt compare

v1.0.0 static block

Two prompts side by side, a vague one and a specific one, with a note on the difference.

Live example

Asking for a fix
✗ Vague
fix the login bug

No context, no constraints, no finish line.

✓ Specific
Users with + in their email can't log in (see issue #214).
Look at src/auth/validate.ts. Keep the public API unchanged.
Add a regression test. Done when npm test passes.

Goal, context, constraints and done-when are all there.

Copy this into your page

```compare
title: Asking for a fix
weak:
  prompt: fix the login bug
  note: No context, no constraints, no finish line.
strong:
  prompt: |
    Users with + in their email can't log in (see issue #214).
    Look at src/auth/validate.ts. Keep the public API unchanged.
    Add a regression test. Done when npm test passes.
  note: Goal, context, constraints and done-when are all there.
```

Fields

FieldMeaning
titleHeading.
weak *The vague version.
strong *The improved version.

Put in order order

v1.0.0 interactive web component counts towards the grade

Learners arrange steps into the right sequence (drag or arrow buttons). Write items in the correct order — they are shuffled for the learner. Worth 1 point; partial credit for items in the right place.

Live example

Copy this into your page

```order
title: The agent work loop
prompt: Arrange the steps of a healthy Codex task.
items:
  - Describe the goal, context, constraints and done-when
  - Let Codex plan, then approve the plan
  - Codex edits code and runs the checks
  - Review the diff yourself
  - Commit or ask for changes
explain: Plan before code, verify before commit.
```

Fields

FieldMeaning
idStable id.
titleHeading.
promptInstruction shown above the list.
items *Steps in the CORRECT order.
explainShown when the order is right.
gradedSet false for practice only. Default: true

Quiz quiz

v1.0.0 interactive web component counts towards the grade

Multiple-choice questions with instant feedback and an explanation. Single answer (answer: 0) or several (answer: [0, 2]). Counts towards the Moodle grade: one point per question.

Live example

Copy this into your page

```quiz
title: Quick check
questions:
  - q: Which file does Codex read automatically for project rules?
    options: [README.md, AGENTS.md, CONTRIBUTING.md]
    answer: 1
    explain: "`AGENTS.md` is loaded automatically; keep durable rules there."
  - q: Which of these belong in a good task prompt?
    options: [Goal, Context, Your favourite colour, Done-when criteria]
    answer: [0, 1, 3]
    explain: Goal, context, constraints and a clear finish line.
```

Fields

FieldMeaning
idStable id; keeps saved answers if you reorder blocks.
titleHeading above the questions.
shuffleShuffle options (stable per learner). Default: false
gradedSet false for a practice-only quiz. Default: true
questions *List of questions.

Decision scenario scenario

v1.1.0 interactive web component counts towards the grade

A situation that unfolds step by step. The learner decides, investigates with a limited budget, or stops an agent at the right moment. Scoring looks at the whole path: decision quality, whether key evidence was checked first, wasted actions, and critical mistakes. A debrief compares the path with an expert's. Three levels: 1 guided (feedback every step, unlimited attempts), 2 realistic (feedback at the end, 2 attempts), 3 expert (budget, ambiguity, 1 attempt).

Live example

Copy this into your page

```scenario
id: demo-scenario
title: The agent wants network access
level: 1
intro: You asked Codex to add a date-formatting helper to a client project.
start: ask
steps:
  ask:
    title: Network request
    situation: Codex asks for network access to run `npm install dayjs`.
    choices:
      - text: Approve once. The task needs the package and you can review the diff
        rating: optimal
        explain: Approving a single, understood command keeps you in control.
        next: done
      - text: Switch to full access so it stops asking
        rating: critical
        explain: That removes the sandbox for everything that follows.
        end: true
      - text: Deny and tell Codex to write the helper without a dependency
        rating: acceptable
        explain: Valid if the project avoids new dependencies. Otherwise you are slowing yourself down.
        next: done
  done:
    ending: true
    situation: The helper is added. You review the diff and commit.
```

Fields

FieldMeaning
id *Required: used for saving progress and unlocking.
title *Scenario name.
level *1 guided · 2 realistic · 3 expert.
introBriefing shown before starting.
budgetInvestigation budget (number of evidence actions).
attempts0 = unlimited. Defaults: L1 unlimited, L2 2, L3 1.
feedbackRating after each step, or only at the end. Default: L1 step, else end.
pointsPoints in Moodle. Default = level (1/2/3).
unlockStay locked until widget `after` reaches `min` (or uses all attempts).
varsPer-learner variants: `{ file: [a.ts, b.ts] }`, use as `{{file}}` in any text.
graded Default: true
versionPractice version. Bump it when you change steps, choices, ratings or scoring; saved attempts restart, best score is kept. Default: 1
start *Id of the first step.
steps *The steps, by id.

Spot the problems spot

v1.1.0 interactive web component counts towards the grade

Learners review a diff, log or file and click the lines that are wrong (and, from level 2, rate how serious each problem is). Scoring rewards finding planted problems, correct severity, and penalises false alarms. The debrief explains every problem and every decoy.

Live example

Copy this into your page

```spot
id: demo-spot
title: Review the agent's change
level: 1
prompt: Codex says it "fixed the login timeout". Find the problems before you approve.
view: diff
filename: src/auth/session.ts
code: |2
   export const SESSION_TTL = 60 * 60;
  -const RETRIES = 3;
  +const RETRIES = 30;
   export function login(user, password) {
  +  console.log("login", user, password);
     return api.post("/login", { user, password });
   }
issues:
  - line: 3
    severity: major
    label: Unexplained retry increase
    explain: 30 retries hides the real problem and can hammer the API. Ask why.
  - line: 5
    severity: critical
    label: Password written to logs
    explain: Secrets must never be logged. Reject this change.
```

Fields

FieldMeaning
id *Required: used for saving progress and unlocking.
title *Task name.
level *1 guided · 2 realistic · 3 expert.
prompt *What the learner should look for.
viewHow to display the content (diff colours + / - lines). Default: "code"
filenameShown above the content.
code *The content to review, verbatim. For diffs write `code: |2` so lines starting with a space keep it.
issues *The planted problems.
decoysLines that look suspicious but are fine — explained if the learner flags them.
severityLearner must also rate severity. Default: off on L1, on for L2/L3.
showCountTell how many problems there are. Default: only on L1.
attempts0 = unlimited. Defaults: L1 unlimited, L2 2, L3 1.
pointsPoints in Moodle. Default = level.
unlockStay locked until widget `after` reaches `min`.
graded Default: true
versionPractice version. Bump it when you change the code lines, issues or scoring; saved attempts restart, best score is kept. Default: 1

Use case usecase

v1.0.0 static block

A realistic scenario: situation → the prompt you would give Codex → what a good outcome looks like → tips.

Live example

Use case
Fix a flaky test
Backend developer

Situation

test_checkout fails about once in ten CI runs.

Prompt

Investigate why tests/test_checkout.py::test_total fails intermittently.
Reproduce it first (run it 50 times). Find the root cause, fix it,
and do not change the assertion. Done when 50 consecutive runs pass.

Good outcome

A short root-cause explanation, a minimal diff, and the loop output.

Tips

  • Ask for the reproduction before the fix.

Copy this into your page

```usecase
title: Fix a flaky test
who: Backend developer
situation: "`test_checkout` fails about once in ten CI runs."
prompt: |
  Investigate why tests/test_checkout.py::test_total fails intermittently.
  Reproduce it first (run it 50 times). Find the root cause, fix it,
  and do not change the assertion. Done when 50 consecutive runs pass.
outcome: A short root-cause explanation, a minimal diff, and the loop output.
tips:
  - Ask for the reproduction **before** the fix.
```

Fields

FieldMeaning
title *Short name of the scenario.
whoRole, e.g. Backend developer, QA engineer.
situation *What is going on.
prompt *The prompt (kept verbatim, shown as code).
outcomeWhat a good result looks like.
tipsPractical hints.
