Checklist checklist

v1.0.0 interactive web component

A personal to-do list for setup steps or readiness checks. Progress is remembered in the learner's browser. Not graded.

Live example

Copy this into your page

```checklist
title: Before your first task
items:
  - text: Open a Git repository and create a branch
    hint: Codex works best when you can diff and revert.
  - Sign in with your ChatGPT account
  - Check permissions with `/status`
done: You are ready to start.
```

Fields

FieldMeaning
idStable id.
titleHeading.
items *Plain strings, or `{ text, hint }`.
doneMessage shown when everything is ticked.

Weak vs strong prompt compare

v1.0.0 static block

Two prompts side by side, a vague one and a specific one, with a note on the difference.

Live example

Asking for a fix
✗ Vague
fix the login bug

No context, no constraints, no finish line.

✓ Specific
Users with + in their email can't log in (see issue #214).
Look at src/auth/validate.ts. Keep the public API unchanged.
Add a regression test. Done when npm test passes.

Goal, context, constraints and done-when are all there.

Copy this into your page

```compare
title: Asking for a fix
weak:
  prompt: fix the login bug
  note: No context, no constraints, no finish line.
strong:
  prompt: |
    Users with + in their email can't log in (see issue #214).
    Look at src/auth/validate.ts. Keep the public API unchanged.
    Add a regression test. Done when npm test passes.
  note: Goal, context, constraints and done-when are all there.
```

Fields

FieldMeaning
titleHeading.
weak *The vague version.
strong *The improved version.

Put in order order

v1.0.0 interactive web component counts towards the grade

Learners arrange steps into the right sequence (drag or arrow buttons). Write items in the correct order — they are shuffled for the learner. Worth 1 point; partial credit for items in the right place.

Live example

Copy this into your page

```order
title: The agent work loop
prompt: Arrange the steps of a healthy Codex task.
items:
  - Describe the goal, context, constraints and done-when
  - Let Codex plan, then approve the plan
  - Codex edits code and runs the checks
  - Review the diff yourself
  - Commit or ask for changes
explain: Plan before code, verify before commit.
```

Fields

FieldMeaning
idStable id.
titleHeading.
promptInstruction shown above the list.
items *Steps in the CORRECT order.
explainShown when the order is right.
gradedSet false for practice only. Default: true

Quiz quiz

v1.0.0 interactive web component counts towards the grade

Multiple-choice questions with instant feedback and an explanation. Single answer (answer: 0) or several (answer: [0, 2]). Counts towards the Moodle grade: one point per question.

Live example

Copy this into your page

```quiz
title: Quick check
questions:
  - q: Which file does Codex read automatically for project rules?
    options: [README.md, AGENTS.md, CONTRIBUTING.md]
    answer: 1
    explain: "`AGENTS.md` is loaded automatically; keep durable rules there."
  - q: Which of these belong in a good task prompt?
    options: [Goal, Context, Your favourite colour, Done-when criteria]
    answer: [0, 1, 3]
    explain: Goal, context, constraints and a clear finish line.
```

Fields

FieldMeaning
idStable id; keeps saved answers if you reorder blocks.
titleHeading above the questions.
shuffleShuffle options (stable per learner). Default: false
gradedSet false for a practice-only quiz. Default: true
questions *List of questions.

Use case usecase

v1.0.0 static block

A realistic scenario: situation → the prompt you would give Codex → what a good outcome looks like → tips.

Live example

Use case
Fix a flaky test
Backend developer

Situation

test_checkout fails about once in ten CI runs.

Prompt

Investigate why tests/test_checkout.py::test_total fails intermittently.
Reproduce it first (run it 50 times). Find the root cause, fix it,
and do not change the assertion. Done when 50 consecutive runs pass.

Good outcome

A short root-cause explanation, a minimal diff, and the loop output.

Tips

  • Ask for the reproduction before the fix.

Copy this into your page

```usecase
title: Fix a flaky test
who: Backend developer
situation: "`test_checkout` fails about once in ten CI runs."
prompt: |
  Investigate why tests/test_checkout.py::test_total fails intermittently.
  Reproduce it first (run it 50 times). Find the root cause, fix it,
  and do not change the assertion. Done when 50 consecutive runs pass.
outcome: A short root-cause explanation, a minimal diff, and the loop output.
tips:
  - Ask for the reproduction **before** the fix.
```

Fields

FieldMeaning
title *Short name of the scenario.
whoRole, e.g. Backend developer, QA engineer.
situation *What is going on.
prompt *The prompt (kept verbatim, shown as code).
outcomeWhat a good result looks like.
tipsPractical hints.
