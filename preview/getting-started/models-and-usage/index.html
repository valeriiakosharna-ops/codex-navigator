Choosing models and managing usage

Match the model and reasoning effort to the task, tell plan limits apart from credits, and keep repeated or long-running work affordable.

For everyone⏱ ~40 minGraded · 5 pt

Why this matters#

Every Codex task spends something: your plan's included usage or, after that, credits. The most powerful model at the highest effort is rarely the right default. It's slower, it uses more, and for a well-scoped fix it isn't better. Teams that pick deliberately get more done within the same plan, and they don't hit the limit on Thursday afternoon.

Model names change. The approach doesn't.

The line-up below is from November 2026. OpenAI releases and retires models often (GPT-5.5 is being retired right now), so the Models page is always the source of truth. What lasts is the method: decide what you need, try the lightest setting that meets it, and compare on the same inputs.

Two dials: model and reasoning effort#

You choose What it changes Start with
Model How capable, how fast and how costly each step is The default your workspace offers
Reasoning effort (Light/Low → Medium → High → Extra high) How long the model thinks before acting The default; raise it for multi-step work with trade-offs
Max Even more thinking time for a single, very hard task Only for the hardest problems
Ultra Splits the task across subagents working in parallel Only when the work really divides into parts. It uses more tokens.
Fast mode (/fast) Same model, faster output, at a higher usage rate When you're waiting on the result and usage isn't tight

Choosing a setting for a recurring task
✗ Vague
Always use the strongest model on Extra high. Quality first.

Fine for a one-off, hard decision. For a nightly job or a stream of small fixes, it burns the plan's limit and adds nothing to quality.

✓ Specific
Nightly changelog draft from merged PRs.
Acceptance: every PR listed, grouped by area, no invented items.
Try: efficient model, Medium → compare 3 nights with the default.
Keep the lightest setting that passes the acceptance check.

Acceptance criteria first, a like-for-like comparison, then the cheapest setting that passes.

Limits, credits and where to check them#

OpenAI Docs
Pricing, usage limits and credits
Officialdocs⏱ 15 min

How included plan usage, credits and API-key usage fit together, plus OpenAI's own tips for making your limits last.

While you study, pay attention to

  • What happens at the limit: a turn that is already running is allowed to finish. After that, Plus/Pro users can buy credits, and Business/Edu/Enterprise workspaces with flexible pricing can buy workspace credits.
  • Tokens vs credits: tokens are what the model reads and writes; credits are what eligible usage costs once your included limits run out.
  • Where to look: the usage dashboard, and /status inside a CLI session. The docs suggest checking every week or two.
  • Which Code Review usage is counted separately (reviews run through GitHub) and which counts towards your general limit.

OpenAI's tips for making limits last, in short

Be precise and leave out unnecessary context. Give only the relevant files. Ask for the format and length you actually need. Keep AGENTS.md small: in a large repo, nest several short files instead of one big one.

Use case
The team that ran out by Wednesday
Delivery manager of a 6-person team

Situation

Since the team started using Codex, most people hit their limit mid-week. Everyone uses the top model on Extra high "to be safe", and a 900-line AGENTS.md is loaded into every task.

Prompt

Look at how our team uses Codex over a typical week (task types, models,
effort, AGENTS.md size). Propose a default model and effort for each task type,
and three changes that reduce usage without lowering the quality of reviewed results.
Mark every assumption you make.

Good outcome

A short policy, for example light settings for scoped fixes and the strong model only for design reviews, plus a plan to split AGENTS.md by directory.

Tips

  • Decide on the quality bar per task type before changing settings, then compare like for like.
  • Fast mode and Ultra are opt-in tools for specific moments, not defaults.
