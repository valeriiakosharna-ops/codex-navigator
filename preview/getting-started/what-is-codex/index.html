What Codex is and where it runs

Codex is OpenAI's coding agent. Learn the surfaces it runs on and pick the right one for each kind of task.

👥 For: Everyone⏱ ~35 min (+ an optional 53-min video)Graded · 3 pt

Why this matters#

Codex is a coding agent. It doesn't just suggest the next line: it reads your repository, runs commands, edits files and reports back. You can reach the same agent from several surfaces, and choosing the right one saves a lot of friction. A common early mistake is running a long task in a place you then need to close, like a terminal on a laptop you're about to shut.

The surfaces at a glance#

Surface Where it runs Best for
Desktop app Your machine, with a project folder Longer tasks, reviewing diffs visually, several chats in parallel
IDE extension Inside your editor Working next to the code you're already editing
CLI (codex) Your terminal Keyboard-driven work, scripting, CI via codex exec
Cloud / web OpenAI's cloud environment Tasks that run on their own while you do something else
Mobile Your phone, connected to the app or cloud Checking on, steering and approving running work away from your desk
Rule of thumb

Pair-programming on code in front of you: use the IDE. Scripts and automation: use the CLI. "Go do this and come back with a PR": use cloud.

How teams actually use it#

Use case
Onboarding into an unfamiliar repository
Developer joining a new project

Situation

You've just cloned a service you've never seen, and you need to fix a bug in it tomorrow.

Prompt

Explain this repository to me: the main modules, how a request flows
from the HTTP layer to the database, and how to run the tests locally.
Don't change any files.

Good outcome

A map of the codebase with file references and the exact test command. Nothing is modified.

Tips

  • "Don't change any files" (or read-only mode) makes exploration safe.
  • Ask your follow-ups in the same chat. The context you built up is what makes the answers good.
