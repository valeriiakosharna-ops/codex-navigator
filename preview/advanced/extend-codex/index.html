Module 4 · Advanced configuration and extensibility

Reusable workflows: skills, plugins and hooks

Turn a recurring team process into a skill people can read and maintain, share it as a plugin, and use hooks for checks that must always run.

For technical specialists⏱ ~55 minGraded · 5 pt

Why this matters#

You'll notice it soon enough: you keep pasting the same multi-step instruction. Release notes, log triage, the PR checklist. Each person on the team does it a little differently, and the output shows it. The Extend Codex Workflows path calls the fix "a reusable Codex skill built around a team process people can understand and maintain".

Codex has three mechanisms for this, and they're easy to confuse:

You need… Use Example
A short, durable rule for every task AGENTS.md (previous topic) "Use pnpm; run lint before finishing"
A repeatable method with inputs and outputs Skill Release notes, incident summary, PR checklist
To share skills (and tools) beyond one repo Plugin A team toolkit installed from the directory
Something that must happen every time, not just when the model remembers Hook Block prompts containing API keys; run a check when a turn stops

Skills#

OpenAI Docs
Build skills
Officialdocs⏱ 15 minadvanced

While you study, pay attention to

  • A skill is a folder with a required SKILL.md: name, description, then the instructions.
  • Locations: $HOME/.agents/skills (personal) and .agents/skills in the repository (shared with the team).
  • The description decides when the skill triggers. Keep each skill to one job and state when it should not be used.
  • $skill-creator drafts a skill for you. Share skills beyond one repo as plugins.

Skill best practices, from the docs

Keep each skill to one job. Prefer instructions over scripts unless you need deterministic behaviour. Write imperative steps with explicit inputs and outputs. Test prompts against the description to check it triggers when it should, and only then.

Use case
A release-notes skill
Team lead who writes release notes every two weeks

Situation

Each release you paste the same 10-line instruction to turn merged PRs into user-facing notes.

Prompt

Use $skill-creator to make a skill called release-notes:
input: a git range (e.g. v1.4.0..HEAD);
steps: list merged PRs, group by feature/fix/internal, drop internal ones,
rewrite titles for end users, flag anything that needs a migration note;
output: Markdown in docs/releases/<version>.md.
Put it in .agents/skills so the whole team gets it.

Good outcome

A reusable skill in the repo. Next time, "write release notes for v1.5.0" is enough.

Tips

  • If you keep correcting the same thing in the output, update the skill, not your prompt.

Hooks#

Skills are followed when the model decides they apply. Hooks run scripts (or MCP tools) at fixed points in the agent loop, whatever the model decides: before or after a tool call, when you submit a prompt, when a turn stops, when a session starts or ends.

OpenAI Docs
Hooks
Officialdocs⏱ 15 minadvanced

The events, the config shape, and how hooks are reviewed and trusted before they run.

While you study, pay attention to

  • The docs' examples of what hooks are for: logging chats, blocking prompts that contain API keys, running a validation check when a turn stops.
  • Hooks you didn't write must be reviewed and trusted before they run. Admins can also ship managed hooks.
  • Several matching hooks run concurrently, so one can't stop another from starting.
