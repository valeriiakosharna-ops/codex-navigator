Module 2: Practical workflows

Make guidance durable: AGENTS.md and config

Stop repeating yourself. Put project rules in AGENTS.md and preferences in config.toml.

⏱ 35 minNavigates: Codex 102: Practical Workflows (OpenAI Academy)Graded · 3 pt

Why this matters#

If you type the same instruction twice ("use pnpm", "run lint before you finish", "never touch migrations/"), it belongs in a file, not in a prompt. AGENTS.md is an open format, a README for agents that Codex loads automatically. config.toml holds your preferences for model, reasoning effort, sandbox, approvals, profiles and MCP servers.

What to put in AGENTS.md#

A useful AGENTS.md is short and accurate. Cover:

  • repository layout (where things live);
  • how to run the project, and the exact build / test / lint commands;
  • engineering conventions and PR expectations;
  • constraints and "do-not" rules;
  • how to verify that work is done.
Use case
Writing your team's first AGENTS.md
Developer on a team of six

Situation

Codex keeps running npm test (the whole suite, 9 minutes) and forgets the lint step.

Prompt

Run /init, then edit the generated AGENTS.md so it says:
- use pnpm, never npm;
- for a quick check run `pnpm test --filter <package>`; full suite only before a PR;
- always run `pnpm lint` before declaring the task done;
- never edit files under db/migrations/ — propose a new migration instead.
Keep it under 40 lines.

Good outcome

A short AGENTS.md checked into the repo. Every teammate's Codex now follows the same rules.

Tips

  • When Codex repeats a mistake, ask it to review what went wrong and propose an AGENTS.md update.
  • Link longer docs (e.g. docs/code_review.md) from AGENTS.md instead of pasting them in.
Best practice

Durable rules go in AGENTS.md (or skills, later). One-off details go in the prompt. Mixing these up is one of the most common mistakes the official guide lists.
