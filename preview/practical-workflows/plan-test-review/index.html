Module 2 · Practical workflows

The plan → build → test → review loop

Make Codex verify its own work, then review the diff yourself or with /review and GitHub code review.

⏱ 35 minNavigates: Codex bootcamp 201: Team workflows (OpenAI Academy recording)Graded · 4 pt

Why this matters#

An agent can produce a lot of code quickly, so the bottleneck moves to verification. Teams that get value from Codex make "done" mean tested and reviewed, not just written.

The loop#

While you watch the bootcamp recordings

Count how often the presenters ask Codex to run the tests. Treat every task that ends without a check as a warning sign.

Review tools#

  • In the desktop app, use the diff panel and comment on specific lines. Your feedback goes into the next turn.
  • /review in the CLI starts a dedicated reviewer that reports prioritised findings without modifying your working tree.
  • GitHub: Codex can review pull requests automatically, or when someone mentions @codex review.

Use case
Second pair of eyes before a PR
Developer finishing a feature branch

Situation

You wrote most of the feature yourself and want a quick independent review before asking colleagues.

Prompt

/review against main. Focus on error handling and on any behaviour
change that is not covered by tests. List findings by severity.

Good outcome

A prioritised list of findings with file and line references. Your working tree is untouched.

Tips

  • Asking for findings "by severity" keeps the important ones from getting buried.
  • Agent review supplements human review. It doesn't replace it.
Common pitfall

Watching Codex step by step instead of working in parallel. Give it a clear done-when, let it run the checks, and come back to review the result.
