Module 1 · Get started with Codex

What Codex is and where it runs

Codex is OpenAI's coding agent. Learn the surfaces it runs on and pick the right one for each kind of task.

⏱ 25 minNavigates: Codex 101: Introduction and Onboarding (OpenAI Academy)Graded · 3 pt

Why this matters#

Codex is a coding agent. It doesn't just suggest the next line. It reads your repository, runs commands, edits files and reports back. You can reach the same agent from several surfaces, and choosing the right one saves a lot of friction. Most people start in the wrong place, for example running a long refactor in a terminal they then need to close.

The surfaces at a glance#

Surface Where it runs Best for
Desktop app Your machine, with a project folder Longer tasks, reviewing diffs visually, running several chats in parallel
IDE extension Inside your editor Working next to the code you are already editing
CLI (codex) Your terminal Fast keyboard-driven work, scripting, CI via codex exec
Cloud / web OpenAI's cloud environment Delegating tasks that run on their own while you do something else
Rule of thumb

Pair-programming on code in front of you: use the IDE. Batch work and automation: use the CLI. "Go do this and come back with a PR": use cloud.

How teams actually use it#

Use case
Onboarding into an unfamiliar repository
Developer joining a new project

Situation

You have just cloned a service you have never seen and need to fix a bug in it tomorrow.

Prompt

Explain this repository to me: the main modules, how a request flows
from the HTTP layer to the database, and how to run the tests locally.
Don't change any files.

Good outcome

A map of the codebase with file references, plus the exact test command. Nothing is modified.

Tips

  • Ending with "Don't change any files" (or switching to read-only) makes exploration safe.
  • Ask follow-ups in the same chat. The context you built up is the value.
