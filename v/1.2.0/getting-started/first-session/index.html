Your first session, safely

Install, sign in, understand sandbox and approvals, and finish a first real task without surprises.

Why this matters#

The first hour with an agent shapes your habits. Two things decide whether that hour goes well: a clean starting point, meaning a Git repo you can diff and revert, and the right permissions, meaning what Codex may do without asking you. Get both right and you can let Codex move fast without worrying.

Install and sign in#

On macOS or Linux the docs give a one-line installer. npm also works on any OS with Node.js:

# official installer (macOS / Linux)
curl -fsSL https://chatgpt.com/codex/install.sh | sh

# or with npm
npm install -g @openai/codex

Then open a project folder and run codex. On first run, choose Sign in with ChatGPT. For Windows options (native app, sandbox, WSL), follow the CLI page below.

Sandbox and approvals: the two dials#

Codex has two separate settings. People often mix them up.

  • Sandbox mode decides what Codex can touch: read-only, workspace-write (edit inside the project) or danger-full-access (no sandbox).
  • Approval policy decides when Codex must ask you: on-request (asks before going outside the sandbox, e.g. network or files outside the workspace) or never.

For a version-controlled project the recommended preset is Auto, which means workspace-write + on-request. For folders without Git, stay in read-only. Network access is off by default.

Common pitfall

Turning on full access "just to stop the prompts" on day one. The prompts tell you what the agent wants to do. Learn the workflow first, then loosen permissions per trusted repo.

Caution

Treat web content the agent reads as untrusted. Prompt injection can make an agent follow instructions hidden in a page.
